# Fixture sources

`SHA256SUMS` locks every file in this directory. Regenerate it only after an
intentional fixture update:

```bash
scripts/update_fixture_hashes.sh
cargo test --test fixture_manifest
```

## Project-generated codec streams

  `h263_*` are generated by `scripts/gen_corpus.sh` with FFmpeg's
  `libaom-av1`, `libvpx`, `libvpx-vp9`, `mpeg2video`, `mpeg4` and `h263`
  encoders.

  to `yuv444p` and encoded on t6 by libaom `aomenc` profile 1 at CQ 30 with

  and QP averaging; all 4,608 decoded bytes match FFmpeg.
- `h264_cabac_p16_mv_48x32` uses the same 48x32 Main-profile setup with a
  random-noise source frame cropped at x=0 and x=8. A temporary x264 trace build
  disables P-skip and all P sub-partitions/intra modes and forces every
  `P_L0_16x16` motion vector to `(+32, 0)` quarter-pel samples (luma +8 pixels,
  4:2:0 chroma +4 pixels). The encoder recomputes residuals against that motion
  vector; FFmpeg verifies the resulting stream. The gate covers non-zero MVD
  parsing/sign, MVP propagation, integer luma/chroma motion compensation and
  edge extension. The decoder test supplies FFmpeg's first frame as reference
  picture 0 and compares the complete P frame.
- `h264_cabac_p16_multiref_48x32` is a three-frame IDR+P+P stream with two
  active L0 references. Its final P picture deliberately mixes the recent P
  and the older IDR: the six macroblocks select reference indices
  `1,0,0,0,1,0`. The fixture exercises CABAC ref_idx unary trees and neighbor
  contexts, per-4x4 reference state, ref-aware MVP availability with the
  A-fallback rule, reference-specific motion compensation and the final
  sample-exact 48x32 P plane.
- `h264_cabac_p16_weighted_48x32` is a two-frame explicit weighted-prediction
  stream with `luma_log2_weight_denom=2`, luma scale/offset `3/8`, and
  `chroma_log2_weight_denom=3` with U/V scale/offset `7/4`. The temporary x264
  build forces the table while P-skip, P subpartitions and P intra modes stay
  disabled. The fixture exercises the pred_weight_table syntax, CABAC slice
  alignment at a non-byte-boundary header end, weighted luma and both chroma
  planes, rounded scaling, clipping and residual reconstruction. The complete
  FFmpeg P frame matches sample-exactly.
- `h264_cabac_p16_fractional_mv_48x32` repeats the random-texture crop pair
  with the temporary x264 build's normal subpel motion search (`subme=2`) while
  still forbidding P-skip, sub-partitions and intra modes. The six final P16
  vectors include `(-6,-9)`, `(8,1)`, `(5,1)`, `(-5,-6)` and `(7,1)`, covering
  fractional quarter-pel luma and eighth-sample 4:2:0 chroma positions. The
  decoder test supplies the FFmpeg IDR frame as reference picture 0 and compares
  the complete 2,304-byte P frame.
- `h264_cabac_p16x8_48x32` uses the same random-texture crop fixture and
  encoder restrictions, with a temporary x264 runtime switch forcing every P
  macroblock to `P_L0_L0_16x8`. x264 report is 100% 16x8 and no skip; the top
  partition vectors begin at `(-32,0)`, `(16,0)` and `(32,0)`. The gate
  exercises the three CABAC mb_type bins, two partition MVDs, partition-level
  MVP/MVD contexts, independent top/bottom motion compensation and one shared
  macroblock residual. The complete FFmpeg P frame matches sample-exactly.
- `h264_cabac_p8x16_48x32` forces every P macroblock to `P_L0_L0_8x16` on a
  source whose left/right 8x16 regions have different translations. x264
  reports 100% 8x16 and no skip; partition vectors include `(-28,0)`,
  `(16,0)`, `(-2,17)` and `(-32,0)`. The gate covers left/right partition MVP
  propagation, two MVD contexts, independent motion compensation and shared
  residual reconstruction, with the complete FFmpeg P frame byte-exact.
- `h264_cabac_p8x8_48x32` enables P_8x8 and sub-8x8 analysis on the random
  source. The P picture mixes 16x16, 8x16 and P_8x8 macroblocks; across the
  P_8x8 quadrants it covers all four sub_mb_type modes (`8x8`, `8x4`, `4x8`
  and `4x4`). The gate therefore exercises the P_8x8 mb_type suffix, all four
  CABAC subpartition trees, 4x4 MVD contexts and caches, independent
  subpartition luma/chroma interpolation and one shared macroblock residual.
  The complete FFmpeg P frame is sample-exact.
- `h264_i_pcm_cabac` is a 16x16 High-4:4:4-Intra `qp=0` CABAC stream using
  100% I_PCM macroblocks. It locks the raw 4:2:0 sample payload, byte
  realignment and arithmetic-decoder restart behavior.
- `h264_i_pcm_cabac_10bit` repeats the I_PCM gate as 10-bit 4:2:0 and stores
  FFmpeg's little-endian `yuv420p10le` output.
- `h265e_c_fixqp_*` are short fixed-QP streams emitted by the source-built C
  MPP encoder used as the H.265 header oracle.
