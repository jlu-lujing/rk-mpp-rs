# Fixture sources

`SHA256SUMS` locks every file in this directory. Regenerate it only after an
intentional fixture update:

```bash
scripts/update_fixture_hashes.sh
cargo test --test fixture_manifest
```

## Project-generated codec streams

- `av1_*`, `film_grain_10bit.ivf`, `vp8_*`, `vp9_*`, `m2v_*`, `mp4_*` and
  `h263_*` are generated by `scripts/gen_corpus.sh` with FFmpeg's
  `libaom-av1`, `libvpx`, `libvpx-vp9`, `mpeg2video`, `mpeg4` and `h263`
  encoders.
- `h264_i32_*` and `h264_i64_*` are local x264 CAVLC streams with FFmpeg
  yuv420p golden output. Their exact generating parameters are recorded in
  `ROADMAP.md` next to the pixel gates.
- `h264_i16_cabac*` and `h264_i4x4_cabac*` are local x264 CABAC streams with
  FFmpeg yuv420p golden output. The fixtures are tiny, deliberately textual
  pictures that isolate I16 DC/AC, chroma residual, multi-macroblock state and
  I4x4 transmission order.
- `h265e_c_fixqp_*` are short fixed-QP streams emitted by the source-built C
  MPP encoder used as the H.265 header oracle.

## C MPP captures

- `av1_cdf/`, `av1_picparams/`, `av1_film_grain/`, `vp9_p*_hw/`,
  `vp8/c_*`, `rc_data_c_probe.txt`, `rc_model_v2_c_*`, `vepu580_*` and
  `p_slice_mmco.264` are captured from the source-built C MPP reference by the
  board scripts under `scripts/board_*`.
- These captures are oracle data, not normal application inputs. Regenerate
  them with the corresponding board script, not by editing bytes manually.

No large third-party conformance suite is stored here. The repository keeps
small project-generated or C-MPP-captured vectors and their hashes; external
corpora remain outside git and are referenced by the board scripts.
