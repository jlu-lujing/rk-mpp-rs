# H.265 Tiles Closeout Implementation Plan

> **状态：已完成（历史计划，2026-11-01 归档）**。tiled 流已逐字节对上：
> 1280x720、两列的 H.265 流 30/30 帧与 C MPP 一致（`scripts/board_regress_hevc.sh`）。
> 本文保留为任务拆解记录；当前状态以 `ROADMAP.md` 为准。

> **For the agent:** REQUIRED SUB-SKILL: use `superpowers:executing-plans` and implement this plan task-by-task.

**Goal:** Make the rkvdec H.265 path decode tiled x265/MPP streams bit-exactly, including non-uniform tile geometry.

**Architecture:** Preserve tile column widths and row heights in the codec parser, emit them through the existing 112-byte hardware packet, and validate the complete path against C MPP on the board. The stream generator must use MPP's encoder because this board's libx265 build does not expose tile options.

**Tech Stack:** Rust 2021 with `libc` only, `cargo test`, board `ssh t6`, `/tmp/mpp-develop/build/test/mpi_enc_test`, `/tmp/mpp-develop/build/test/mpi_dec_test`.

### Task 1: Add a reproducible tiled-stream fixture

**Files:**
- Create: `scripts/gen_hevc_tiles.sh`
- Test: board command output and `rk-mpp-rs hevc /tmp/hevc_tiles_720p.hevc`

**Step 1: Create the stream generator**

The script creates 30 frames of 1280x720 yuv420p input, copies MPP's H.265
encoder config to `/tmp`, enables `auto_tile`, then encodes an Annex-B stream.

**Step 2: Run it**

Run: `./scripts/gen_hevc_tiles.sh`

Expected: `/tmp/hevc_tiles_720p.hevc` exists and `rk-mpp-rs hevc` reports
`tiles=true`.

**Step 3: Capture the current failure**

Decode once with MPP and once with Rust, convert MPP NV12 to planar, and run
`cmp`. Expected before the fix: FAIL or obvious corruption. Save the first
different byte offset in `/tmp/hevc_tiles_cmp.log`.

### Task 2: Preserve tile geometry during PPS parsing

**Files:**
- Modify: `src/codec/hevc/parser.rs`
- Test: `src/codec/hevc/parser.rs`

**Step 1: Write failing parser tests**

Add tests for:

1. Uniform 2x2 tiling derives the expected widths/heights from the SPS CTB grid.
2. Non-uniform explicit `column_width_minus1[]` and `row_height_minus1[]`
   values survive parsing instead of being discarded.

**Step 2: Run the tests**

Run: `cargo test hevc::parser::tests::parses_tile_geometry -- --nocapture`

Expected: FAIL because `Pps` has no geometry fields.

**Step 3: Add minimal parser state**

Add:

```rust
pub tile_column_widths: Vec<u32>,
pub tile_row_heights: Vec<u32>,
```

Store explicit values during parsing. For uniform spacing, fill the vectors in
`build_pps_packet`, where the SPS CTB dimensions are available.

**Step 4: Verify**

Run: `cargo test hevc::parser -- --nocapture`

Expected: all parser tests PASS.

### Task 3: Emit exact tile geometry in the hardware packet

**Files:**
- Modify: `src/codec/hevc/hw.rs`
- Test: `src/codec/hevc/hw.rs`

**Step 1: Write a failing packet test**

Construct a non-uniform 3-column PPS with widths `[7, 9, 4]`, build the packet,
and decode the 12-bit width slots back out. Assert those exact values because
MPP writes `width - 1`.

**Step 2: Run the test**

Run: `cargo test nonuniform_tile_geometry_reaches_pps_packet -- --nocapture`

Expected: FAIL because the packet currently recomputes only uniform geometry.

**Step 3: Use parsed geometry**

Update `tile_geometry()` to return parsed widths/heights when
`uniform_spacing == false`, and derive uniform geometry otherwise. Keep the
packet layout at 20 columns x 12 bits and 22 rows x 12 bits.

**Step 4: Verify**

Run: `cargo test tile_geometry -- --nocapture`

Expected: uniform and non-uniform packet tests PASS.
